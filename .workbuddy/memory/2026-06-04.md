## 修复微信内置浏览器音频播放问题

**问题**：项目在手机微信内浏览时，阅读中的点评、小结音频都没有播放出来。

**原因**：微信内置浏览器严格限制音频自动播放，必须由用户手势触发。`_annotationAudio.play()` 是在原文音频的 `onended` 回调中触发的，没有用户手势，被微信直接拦截。

**修复方案**：在 `player.init()` 中添加了微信音频解锁逻辑：
- 监听 `touchstart` / `touchend` / `mousedown` / `click` 首次用户手势
- 对手势触发时，对 `audio` 和 `_annotationAudio` 各做一次 `play()→pause()` 预热
- 解锁后，后续在 `onended` 回调中调用 `play()` 就能成功

**修改文件**：`frontend/index.html` — `player.init()` 函数

**状态**：代码已修改，待部署验证

## 修复用户信息/密码/留言页滚动失效

**根因**：三个页面的内联 `min-height: 100vh` 与 `.page` 基类的 `flex: 1` 产生冲突。flex 容器中 `flex: 1` 配合 `min-height: 0` 才能让 `overflow-y: auto` 正常触发滚动；`min-height: 100vh` 强制撑满视口导致 flex 无法正确计算溢出，滚动失效。

**修复**：移除 `userInfoPage`、`userPasswordPage`、`userMessagePage` 内联的 `min-height: 100vh`，让基类 `flex: 1; min-height: 0; overflow-y: auto` 正常生效。

**commit**: 4ead461（已推送）

## feat: 阅读页屏幕常亮 (Wake Lock API)

**需求**：手机阅读时长时间无操作会息屏，影响阅读体验。

**实现**：
- 使用 Web 标准的 `navigator.wakeLock.request('screen')` API
- 进入阅读页（`showPage('readerPage')`）时激活常亮锁
- 返回目录页（`homeBtn` 点击）时释放常亮锁
- 监听 `visibilitychange` 事件，用户切走再切回来时自动重新申请
- 不支持 Wake Lock 的浏览器静默降级（不影响功能）

**兼容性**：Chrome 84+、Safari 16.4+、Edge 84+ 均支持。微信内置浏览器（基于 Chromium）也支持。

**commit**: 0919bf5，已 push

## 修复 Nginx 静态规则拦截图片请求导致 404

**问题**：添加 `location ~* \.(png|jpg|...)` Nginx 静态文件规则后，book_icons 全部 404、wechat_qrcode.png 也 404。

**根因**：Nginx 的 regex location 优先级高于 prefix location，`location ~* \.(png|...)` 拦截了所有 .png 请求直接去 frontend/ 目录找文件，不再代理给 Flask。但 book_icons 的 Docker volume 映射是从宿主根目录到容器内 frontend/book_icons，路径不匹配。

**修复**：
- 删除 Nginx 中新增的静态文件规则（恢复原来的 proxy 架构）
- 在 Flask `backend/main.py` 中新增 `/wechat_qrcode.png` 路由，由 Flask 统一服务所有静态文件
- 所有静态文件请求走 Nginx → Flask proxy，Flask 通过各路由从 frontend/ 目录提供服务

**commit**: 2d5be52

## 密码安全页设备信息不显示 — 修复

**现象**：微信内打开密码安全页，设备名称和设备ID都显示 `--`

**根因**：设备信息设置代码在 `loadUserProfile()` 函数中（设置 `deviceName`、`deviceDetail`），但 `goToPassword()` 只调了 `showPage('userPasswordPage')`，**漏调了 `loadUserProfile()`**。`goToUserInfo()` 有调用但 `goToPassword()` 没有。与微信环境无关。

**修复**：`goToPassword()` 加一行 `loadUserProfile()` 调用。

## 公版书籍匿名用户系统

**需求**：公版书籍默认允许未登录的匿名用户阅读前3节，第4节时提示注册登录；匿名用户无手机号无密码，只有 device_id 和设备信息；菜单隐藏用户信息和密码安全。

**实现**：

### 后端 api.py
- 新增 `POST /api/auth/anonymous` 接口：
  - 接收 `device_id` + `device_info`
  - 先查 `users` 表是否存在 `device_id` 匹配且 `phone IS NULL` 的匿名用户
  - 存在则更新 device_info 返回；不存在则 `INSERT` 新建（phone=NULL, password=NULL, role='user'）
  - 返回 `{user, military_rank, is_new}`

### 前端 index.html
- 新增 `openBookAsGuest(bookId, title, iconPath)` 函数：
  - 已登录（有 phone）→ 直接 `openBookCatalog`
  - 已登录（匿名）→ 直接 `openBookCatalog`
  - 未登录 → 调 `/api/auth/anonymous` 注册/登录 → 设置 `state.currentUser` → `openBookCatalog`
- 公开页书籍卡片 `onclick` 从 `promptLogin()` 改为 `openBookAsGuest(...)`
- `openBookSection()` 新增匿名用户第4节拦截：`!state.currentUser.phone && sectionNumber > 3 → alert('请注册登录，解锁更多阅读内容')`
- 新增 `updateProfileCardAnonymousItems(user)` 函数：匿名用户隐藏 `profileCardUserInfo` 和 `profileCardPassword` 菜单项
- `onLoginSuccess()` 中调用 `updateProfileCardAnonymousItems(user)`；匿名用户不启动 `startDeviceCheck()`
- `showPage()` else 分支也调用 `updateProfileCardAnonymousItems(state.currentUser)`
- `logout()` 已正确清除 `state.currentUser` 并跳转 `publicPage` ✅
