## 系统性修复反复操作导致页面崩溃

### 根因
三个崩溃场景有共同根因——并发操作无保护，导致资源堆积：

| 场景 | 根因 | 后果 |
|---|---|---|
| 菜单反复切换 | showPage() 无防抖 + loadBooks() 并发 | DOM 重复渲染堆积 |
| 播放/暂停反复 | toggle() 无防抖 → play() 并发 → _playNext() 多链叠加 | 音频资源泄漏 + 状态混乱 |
| 标签来回点击 | 无防抖 + showTab() 每次 renderTabs() 重建 DOM | DOM 频繁销毁/重建 |

### 修复内容

**播放器 (player):**
- `toggle()`: 300ms 防抖 (`_toggleCooldown`)
- `play()`: 并发锁 (`_playLock`)，所有退出路径释放
- `_playNext()`: 并发锁 (`_playNextLock`)，防止多个播放链同时运行
- `stop()`: 释放 `_playLock` + `_playNextLock`（安全网）

**页面切换 (showPage):**
- 300ms 防抖 (`_showPageCooldown`)
- 离开阅读页改为调用 `player.stop()`（以前只清理 TTS+音频事件，不够彻底）

**标签切换 (analysisManager):**
- tab onclick: 300ms 防抖 (`_tabClickCooldown`)
- `showTab()`: 仅在实际切换标签时才调用 `renderTabs()`（避免无效 DOM 重建）

## 第三轮全面修复：addEventListener 监听器泄漏 + 系统性清理

### 发现的核心问题
经三个维度并行审计（事件监听器、DOM/定时器/内存、页面导航流程），真正的崩溃根因是：

1. **`_annotationAudio` timeupdate 监听器永不删除**（最严重）
   - `_playQuoteAudio` 和 `_playCommentAudio` 每次通过 `addEventListener('timeupdate', handler)` 注册
   - `_finishInsertPoint` 只清除 `on*` 属性，**不清除 addEventListener 注册的监听器**
   - 同一节播放 N 个点评 → 累积 N*2 个 timeupdate 回调 → 每个都执行 DOM 操作 → 崩溃

2. **`startDeviceCheck()` 定时器创建后立即清除** — 设备检查完全失效

3. **`_checkTTSStatus()` 永久轮询** — 非 timeline 模式下每 5 秒发网络请求，永不停

4. **`showPage` 无统一清理** — 离开页面时 analysisManager 轮巡/tabs/调试定时器残留

5. **`browse.loadBooks` 异步回调操作过期 DOM** — 导航离开后 fetch 回调仍 appendChild

### 修复内容
1. `_finishInsertPoint` / `_finishSummaryPlayback` / `player.stop()`: 重建 `_annotationAudio = new Audio()` 彻底清除
2. 删除 `startDeviceCheck()` 中错误的 clearInterval
3. `_checkTTSStatus()` 用 `this._ttsCheckInterval` 存储，`stop()` 中清理
4. `showPage`: 离开 readerPage → 清理 analysisManager 轮巡/tabs、调试定时器、TTS 轮询
5. `browse.loadBooks` + `_loadGen` 版本号防过期回调
6. `_preloadAllAudio` 预加载后清理临时 Audio
7. `_playAnnotationSegment` 移除冗余 removeEventListener
8. 3 处未追踪 setTimeout → `_safeSetTimeout`

## 修复🔖书签图标位置漂移到评论区

### 根因
`#bookmarkIcon` 是 `position:absolute` 放在 `.chalkboard`（`overflow:hidden`，不滚动）内，
但文字滚动的容器是 `.chalk-text`（`overflow-y:auto`）。
`_showBookmarkAt` 使用 `chalkboard.scrollTop`（始终 0）计算位置，
导致滚动后书签偏移到评论区。

### 修复 (e63cdc4)
1. `#bookmarkIcon` 从 chalkboard 移到 chalk-text 内部
2. 定位参考从 chalkboard 改为 chalkText，使用 `chalkText.scrollTop`（实际滚动值）
3. 边界限制基于 `chalkText.clientHeight` 而非 `chalkboard.clientHeight`
4. 添加 `pointer-events:none` 防止书签遮挡点击

## 断点书签和音频位置计算错误修复 (261186e)

### 问题
断点在中途位置时：(1)书签未显示在断点附近，显示在前面很远 (2)音频没有在断点位置开始播放

### 根因分析
发现 4 个关联 bug，核心问题是 `text_position`（段内偏移）和 `current_position`（全局位置）在不同上下文中被混淆使用：

**Bug1: `_restoreBookmarkAndPosition` 第一次调用时 audioSegments 为空**
- `textPos` 取自 `text_position`（段内偏移，如 100），但被直接当作全局位置使用
- `savedPosition = 100` 而不是实际的 600（全局位置）
- 修复：audioSegments 为空时优先用 `current_position`（始终是全局位置）

**Bug2: 音频断点恢复 charTimeline 回退计算错误**
- `textPos = text_position`（段内偏移），但代码又减去了 `start_char`
- `segOffset = 100 - 500 = -400` → 截断为 0 → 音频从段首开始播放
- 修复：`text_position` 存在且 `segment_id` 存在时，直接使用不减去 start_char

**Bug3: `_playTextSegment` 断点显示比较错误**
- `textPos`（段内偏移）与 `seg.start_char`/`seg.end_char`（全局边界）比较
- 如 `100 > seg.start_char(500)` 永远是 false → 断点恢复逻辑不触发
- 修复：先将 `text_position` 转换为全局位置再比较

**Bug4: `setupScrollListener` 和 `_doShowBookmark` 使用错误的滚动容器**
- 滚动监听器绑在 `chalkboard`（overflow:hidden），scroll 事件永不触发
- `_doShowBookmark` 也设置 chalkboard.scrollTop（无效）
- 修复：全部改为 `chalkText`（overflow-y:auto 的实际滚动容器）

### 关键认识
- `text_position` 在有 `segment_id` 时 = 段内偏移（相对位置）
- `current_position` = 全局字符位置（绝对位置）
- 之前代码在多处混淆了这两种语义，导致加减 start_char 逻辑反复出错

## 修复黑板空位下文字被强制滚上去 (de1f614)

### 问题
断点恢复时，黑板下方还有大片空白，但文字已被强制 scroll 上去看不见。

### 根因
1. `_restoreBookmarkAndPosition` 用比例 `scrollPercent * (scrollHeight - clientHeight)` 计算 scrollTop，无论内容是否溢出都强制执行
2. `_scrollToTarget` 的 `+50px` 冗余量把目标字符推到视口下方过远

### 修复
1. `_restoreBookmarkAndPosition`: 改为先检测断点字符是否在可视区域内（用 getBoundingClientRect），只在不可见时才滚动，定位到容器顶部附近留 20px 上文
2. `_scrollToTarget`: 冗余量从 `+50` 降为 `+5`

## 修复断点恢复时点评原文引用高亮消失 (fffdb9d)

### 问题
reading 状态进入阅读页，点评1的原文引用没有高亮划线。返回目录再进入，高亮正常。

### 根因
`_restoreBookmarkAndPosition` 先调用 `revealCharsUpTo(savedPosition)` → 通过 rAF 分批 reveal，每帧清除 `annotated` 类（`classList.remove('annotated')`，用于主线播放清理残留高亮）。

紧接着同步调用 `_highlightAnnotation(ann)` → 给 chars 39-64 添加 `annotated`。

rAF 回调随后执行 → 把刚添加的 `annotated` 全部清除 → 高亮消失。

二次进入时状态变成 `read`，走同步 `revealAll`（不清除 `annotated`），所以"返回再进就好了"。

### 修复
1. `revealCharsUpTo(index, options)` 新增 `skipAnnotationClear` 参数
2. 断点恢复调用的两处 `_restoreBookmarkAndPosition` 传 `{skipAnnotationClear: true}`
3. 主线播放中的 7 处 `revealCharsUpTo` 调用不受影响（仍清除 `annotated`）

## 断点系统全面规范化重构 (017dfbf)

### 发现的核心问题
1. **DB 没有 text_position 字段**：前端发送但后端只存到 current_position 列，字段名歧义
2. **text_position 口径不一致**：文本段中=段内偏移，点评播放中=全局位置
3. **登录/未登录恢复行为不一致**：localStorage 有 text_position → 正确；API 返回没有 → 走进错误分支
4. **global charTimeline vs 段内 char_timeline 混用**：之前已修(552bbbb)

### 后端变更
- `reading_progress` 表新增 `text_position INT` 列（自动迁移已有数据库）
- `update_progress_v2` 同时存储 `text_position`(段内偏移) + `current_position`(全局位置)
- API 接收并传递 `current_position`

### 前端变更
- `saveProgress`: 统一 `text_position` = `pos - start_char`（始终段内偏移），非文本段用 `_lastTextSegmentId` 查段信息计算
- 新增 `skipApi`/`skipLocal` 参数控制保存目标
- **删除**点评触发(行2762)和小结触发(行5203)的 saveProgress（段结束时已存）
- **新增**`_onSegmentEnd` 中文本段结束时保存
- **新增**`_updateDisplayByTime` 中每100字存 localStorage（`{skipApi:true}`，不调后端避免卡顿）
- `play()` 恢复逻辑修复: `segOffset` 始终取段内偏移值（新旧数据兼容）

### 断点数据规范（最终版）
| 字段 | 含义 | 一致性 |
|------|------|--------|
| `text_position` | 段内文字偏移 | ✅ 始终段内偏移 |
| `audio_position` | 段内音频时间(秒) | ✅ 始终段内 |
| `current_position` | 全局文字位置 | ✅ 始终全局 |
| `current_section_id` | 当前节ID | ✅ |
| `current_segment_id` | 当前文本段ID | ✅ |

### 保存时机
| 时机 | 存储方式 | 说明 |
|------|---------|------|
| 离开阅读页 | API + localStorage | 最终位置 |
| 每段音频结束 | API + localStorage | 段结束时 |
| 段内每100字 | localStorage only | 防异常退出丢进度 |
| 点评/小结触发 | ❌ 已删除 | 段结束时已保存 |
