## 音频时间轴修复（完整流程，共9版迭代）

### 问题
"修复音频时间轴"弹窗：指定节时无法加载节列表 → 修复时全部跳过

### 迭代修复过程
1. **v1** - 后端缺 `/books/{id}/sections` 路由 + 前端状态未恢复
2. **Git凭据过期** → 配置 GitHub Personal Access Token 解决推送问题
3. **v2** - audio_duration 全为0 → 从磁盘MP3读取真实时长（纯Python解析帧头）
4. **v3** - 所有segment指向同一音频文件 → 改为按字符位置比例从整节总时长分配绝对时间
5. **v4** - v2遗留旧char_timeline阻止重新生成 → 增加 force 强制覆盖模式
6. **v5-v7** - glob兼容性排查（Docker overlayFS上glob.glob()返回空）→ 改用os.listdir+fnmatch
7. **v8** - get_mp3_duration对百度TTS非标准MP3全返回None → 增加ffprobe兜底
8. **v9** - MP3时间裁剪损坏帧导致ffmpeg concat失败 → 改为整块拼接策略 ✅ 最终成功

### 关键发现
- Docker中glob.glob对section_*.mp3返回空（ls/listdir正常）→ listdir+fnmatch替代
- 百度TTS输出非标准MP3 → 纯Python帧解析全部失败，ffprobe可靠
- MP3帧边界裁剪(-ss -t -acodec copy)会损坏文件 → 整块拼接或需重编码裁剪
- TTS块文件名序号与字符顺序不一致(如section_662_3.mp3是第0块) → 按时长比例分配字符范围

### v9最终方案
- os.listdir+fnmatch查找TTS分块文件
- ffprobe统一测时长
- 每个segment按字符重叠匹配TTS块，整块使用不做裁剪
- 单块→直接复制；多块→ffmpeg concat demuxer拼接
- 生成新segment文件 + char_timeline + 更新DB

- segment #1: 28字, 13.4s (2个TTS块拼接)
- segment #2: 211字, 19.9s (4个TTS块拼接)
- segment #3: 31字, 3.0s (2个TTS块拼接)
